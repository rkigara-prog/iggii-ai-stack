# Explicit failure routing correction

Privacy generation now structurally requires retained decisions to be educational and risk-free, and rejected decisions to carry at least one existing policy risk. Ambiguous responses remain possible and are blocked by the unchanged validator. No decision is repaired, fabricated, or promoted. The installed grammar backend accepted nested anyOf and boolean enums; uniqueItems remains enforced by the existing validator rather than the new generation schema.

Apply `updateFailure()` from `build-explicit-failure.cjs` to a fresh private export of each current production stage. Inspect the entire diff and preserve identifiers, credentials, schedule activation, output roots, retention settings, and existing error-workflow binding. This is a local builder, not an automatic deployment. Generated exports and operational evidence must remain private.

Supported work nodes route caught failures to an explicit metadata recorder and StopAndError, including manual executions. Success guards reject partial batches when the same node also emitted an error. Five recognized noResearch IF gates are replaced by full-batch boolean validation and pure Code filters because IF V2 can swallow condition errors into its false branch. Trusted producer outputs explicitly normalize absent flags to false; the gate itself rejects missing or nonboolean flags. Producer pairing remains unchanged, while each filter preserves its own input indices. Unknown gates fail the build.

Synthetic native acceptance covered model schema compatibility, ordinary retain/reject responses, manual failure, partial command batches, repeated nodes, child errors, scheduled failure, normal mixed routing, malformed routing values, and a filter fault. Synthetic adversarial testing establishes structure, not semantic privacy accuracy. Raw execution retention stayed disabled. Temporary workflows were archived afterward.

Limitations: validation is atomic across the input batch; sibling branches are not a transaction and cannot undo previously completed side effects. A recorder storage outage stops execution visibly but can prevent terminal metadata or local alert persistence. Alerts remain local-only. Error Trigger handling is retained as a fallback; manual failures do not rely on it. No monitoring schedule or external destination is introduced.

Release: run existing CI plus the two correction suites; review exact-head results; back up all three live workflows and helper hashes; publish corrected stages only during the approved window; explicitly read back privacy settings and schedule/binding state. Existing stage-result helper supports the recorder, so no helper replacement is required when its reviewed hash matches. Run one separately authorized production cycle and verify actual content outcome, lineage, and pointers. Do not reset an old failed run to create success. Roll back to the fresh private workflow backups if required, preserving artifacts and evidence. Repository merging must not reconcile unrelated shared AI services.
