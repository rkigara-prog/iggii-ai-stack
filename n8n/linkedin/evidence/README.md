# Content evidence policy 1.0

The production research stage now retrieves shortlisted public pages before final
assessment. `home-chat` remains the semantic assessor. Its support, authority and
origin assessments are recorded as **model judgments**, never deterministic proof
or independent verification. Human editorial review remains required.

## Research and acceptance

1. Existing Brave discovery/recovery supplies at most four recovery groups and three
   foundation groups. The shortlist keeps up to four URLs per group and 18 unique URLs
   overall. URLs come from approved public research, not private transcripts.
2. `retrieve.cjs` fetches serially, checks/pins public DNS addresses and every redirect,
   rejects credentials/nonstandard ports, caps responses at 3 MB, and requires usable
   HTML text. Challenge pages, unsupported content types and failed requests remain
   unavailable. No paywall bypass or PDF extraction is implemented.
3. Cache records preserve requested, final and canonical URLs, publisher, publication
   metadata when present, retrieval timestamp, raw/text hashes and stable passage IDs.
   Publication metadata is an observed page field, not a verified event date. Full HTML
   and extracted text are retained; each model source receives at most 14,000 characters
   of whole passages. Omitted passage counts are explicit. A missing necessary passage
   requires deferral, never replacement with a search snippet.
4. Final ranking uses the existing model node. Each proposed material claim binds to
   source and passage IDs with exact quotes. The gate verifies those bindings, requires
   explicit judgments for scope/attribution/dates/quantities/products/sectors/uncertainty,
   checks numeric identifiers, and blocks selected obvious scope/attribution conflicts.
   These limited checks do not prove natural-language entailment. Invalid evidence is
   never replaced with a lexical window, and no fallback topic is manufactured.
5. Primary eligibility also requires an explicitly vetted official/research host; a model cannot elevate a news site to primary. Unlisted authorities defer for review. Each cited source needs an eligible role, an origin method and a page-bound basis
   for that origin judgment. Unknown origins remain unresolved. Distinct domains alone
   are insufficient. Default acceptance requires relevant primary evidence and two
   eligible distinct origins on different hosts. Promotional/syndicated origin bases
   cannot qualify. A model can still misinterpret a passage: the original source
   judgments are preserved for human review.
6. **Narrow single-source exception:** an exact attributed statement from an official
   NIST/CISA/Microsoft/AWS document, or the vendor's own release status. Claim text must
   be `Publisher states: EXACT PASSAGE QUOTE`; source must pass the documented official
   host and content-path restriction, be primary, and have a valid origin basis. Only
   `document_statement` and `release_status` qualify. Efficacy, guaranteed outcomes,
   compliance, comparative superiority and community posts are excluded. This proves
   passage occurrence and policy eligibility, not the truth of the publisher's claim.
   Unlisted authorities defer until reviewed and explicitly added; no model-created
   exception is honored.
7. Accepted candidates use `evidence_bound`, not `verified`. A cycle with no eligible
   topics creates a completed plan with deferred topics. It preserves the same five
   output files and archive/index behavior; no evidence threshold is lowered.

## Full-prose review

The existing planner records `fullProseReview` and human review flags on proposed
editorial prose. Existing evaluation writing now uses `evaluation/prose_review.py`:
all sentences are checked, including statements omitted from the writer's claim list.
An exact approved claim retains its prior evidence/judgment limitations. Every other
sentence goes to human review, including paraphrases and recommendations. A review
flag is not an assertion that the sentence is false. This is deliberately conservative
coverage, not a new semantic model or a production post-drafting stage.

Reviewers should resolve each unmatched assertion against the evidence, preserve
attribution and qualifiers, and label proposed advice as advice. Approvals and edits
remain human records in Reviews; automation does not consume them. Webinar review
still precedes drafting. LinkedIn publishing is disabled.

## Deployment and rollback

`connect.py` patches an exported three-stage configuration while preserving schedules,
credentials and settings. The native API deployment replaces/publishes enrichment and
planning only; it does not restart containers or inference. The sanitizer remains
unchanged. Helpers run under the existing n8n identity, GID 1800 for shared outputs.

Keep exports and helper backups private. Rollback requires no content execution in
progress: restore the backed-up enrichment/planner nodes/connections/settings through
the native API, publish those versions, and restore backed-up pipeline/archive helpers.
Retain new evidence, review records and completed archives. Do not import an inactive
Git template over a live workflow. Monday remains 07:00 America/New_York.

## Validation limits

One focused gate uses the retained failure families, valid two-source and narrow
single-source acceptance cases, unavailable pages, unsafe scope/quantity claims,
syndication, promotion, unknown judgments, bad passage IDs and omitted prose assertions.
It tests policy behavior using stipulated judgments, not semantic-model accuracy.
One controlled production cycle follows deployment. No model comparison is repeated.
Human editing effort and alternative-writer quality remain unmeasured.
